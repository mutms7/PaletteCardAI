# Collecting PaletteCard data

The model recognizes exactly five classes: `flower`, `heart`, `ring`, `cake`,
and `balloon`. The repository includes an optional Wikimedia Commons Action
API acquisition tool, but it never runs automatically. You can also collect
your own photos or use public-domain/licensed images. Keep the attribution
manifests generated by the tool (`data/attribution.csv` and
`data/attribution.json`) with the project.

## Optional Wikimedia Commons starter set

Preview candidates without downloading:

```powershell
python scripts/download_commons_dataset.py --dry-run --per-class 60 `
  --user-agent "PaletteCardAI/0.1 (https://your-site.example/contact)"
```

The default categories are:

```text
flower  = Close-up photographs of flowers
heart   = Heart symbols
ring    = Wedding rings
cake    = Birthday cakes
balloon = Toy balloons
```

The User-Agent is required for both preview and download because preview still
calls the live Commons API. It must identify PaletteCard and include your
contact URL, email, or Commons `User:` account. After reviewing the candidate
list, run the same command without `--dry-run`.
Override a category with a repeatable argument such as
`--category flower="Flowers by color"`. The tool uses sequential requests,
polite pacing, maxlag/retry backoff, 1024px thumbnails, and a strict
Public Domain/CC0/CC BY/CC BY-SA allowlist. It rejects unknown,
noncommercial/no-derivatives, SVG/GIF/TIFF, corrupt, tiny, oversized, and
duplicate files. Splits are deterministic and balanced at 70/15/15 by default.
Average/difference perceptual grouping catches common resize, crop, and
burst-like variants; still inspect contact sheets for session leakage beyond
what hashes can recognize.
Accepted images are atomically streamed into the target and recorded one at a
time, so Ctrl-C leaves a valid `--resume` manifest. Concise progress is shown
by default; use `--quiet` to suppress it. API retry policy is separate from
shorter media download timeout/retry policy.

Commons metadata is not a legal or copyright warranty. The raw license fields,
source/page URLs, creator/credit, SHA-256, dimensions, and timestamp are kept
in both UTF-8 manifests so you can verify every image before redistribution or
commercial use. Contact sheets in `artifacts/dataset_audit/` show local names,
source titles, and split assignments for manual review.
The manifests also preserve raw license fields plus normalized `usage_terms`
and `attribution_required` values; CC BY/CC BY-SA entries are accepted only
with a creator and canonical Creative Commons license URL.
`attribution.csv` is the authoritative manifest. `attribution.json` is derived
from it and includes a matching SHA-256/generation ID; resume repairs a missing
or stale JSON sidecar from CSV.

The downloader writes `data/REVIEW_REQUIRED`. Inspect every contact sheet and
verify labels, duplicates, creator, and license fields. This is human quality
review, not a legal warranty. Training refuses a Commons manifest until you
explicitly create a receipt:

```powershell
python scripts/approve_dataset.py --reviewer "Your name" --note "Reviewed contact sheets and licenses"
```

The receipt records the manifest SHA-256 and becomes invalid if the manifest
changes. The downloader writes images and manifests atomically, updates the
manifest after each image, and on `--resume` fails clearly on missing,
mismatched, or orphan raster files. It never deletes files.

The tool refuses a non-scaffold target unless `--resume` is explicit and never
offers recursive deletion. Raster files are local training data and should not
be committed; preserve the attribution manifests for review. A later resume
run preserves existing split assignments and only fills missing class counts.

The expected layout is:

```text
data/
  train/{flower,heart,ring,cake,balloon}/
  val/{flower,heart,ring,cake,balloon}/
  test/{flower,heart,ring,cake,balloon}/
```

Use a real object as the label, not its dominant color. A red cake is still a
cake. Include centered and slightly off-center examples, different lighting,
backgrounds, angles, and colors. Avoid exact duplicates and avoid placing
near-identical frames from one photo session in multiple splits (that is data
leakage).

As a learning minimum, use at least 30 images per class total (20/5/5 split).
For a more useful first model, aim for 100–200 per class (70/15/15 or
70/20/10). The folders can contain JPG, JPEG, PNG, WEBP, or BMP. Remove
corrupt files before training.

Run `python scripts/prepare_dataset.py` to create all folders. Then copy files
into the appropriate class and split folders. The training command validates
all five class folders and refuses incomplete layouts.
